Build a complete “Project Settings” module/tab for the existing Tazq application.

IMPORTANT:
- First inspect the existing application, database schema, routes, components, authentication, roles/permissions, project module, task module, defect module, workspace, finance-related structures, custom fields and notification structures.
- DO NOT create duplicate entities where an existing entity already exists.
- Reuse existing components, APIs, database tables/models and design system wherever possible.
- Do not break any existing functionality.
- Follow the existing Tazq visual language, but make this page feel enterprise-grade, clean, modern and organized.
- This is a settings/configuration area, NOT a dashboard.
- All settings must persist to the database.
- Changes should take effect throughout the project wherever applicable.

==================================================
1. PROJECT SETTINGS LOCATION
==================================================

Add a “Settings” tab inside the existing Project workspace/sub-navigation.

The project navigation should continue to contain the existing modules such as:
- Overview
- Planning
- Tasks
- Quality / Defects / Test Cases
- Workspace
- Finance (only when enabled)
- Reports
- Settings

Do not replace the global Tazq sidebar.

Project Settings should open as:

Project Settings
Project Name / Code

Internal settings navigation on the left:

1. General
2. Planning
3. Finance
4. Quality & Delivery
5. Collaboration
6. Access
7. Notifications
8. Customization

Right side contains the selected settings.

Use a clean enterprise settings layout similar to modern SaaS applications.

==================================================
4. FINANCE SETTINGS
==================================================

This is extremely important.

Create a Finance settings section.

Primary setting:

Track Finance
ON / OFF

When OFF:
- Finance tab should not be visible in project navigation.
- Finance-related project calculations should not be active.
- Existing project finance data must NOT be deleted.
- Turning Finance ON again should restore access to existing finance data.

When ON:
- Finance tab becomes available.
- Project can track budgets, expenses, resource costs and other finance information.

Do not expose accounting functionality.

Tazq is tracking project financial intelligence, not replacing accounting software.

--------------------------------------------------
4.1 PEOPLE COST
--------------------------------------------------

Setting:

Track People Cost
ON / OFF

If ON, project can calculate resource cost based on:

Hours Worked × Internal Cost Rate = Resource Cost

Do NOT display “Member Salary” as the normal project setting.

Use:

Internal Cost Rate

Example:

Rahul
₹1,250 / hour

Project Settings should control whether people cost information is visible.

Create:

People Cost Visibility

Options:

Organization Admin
Finance
Project Manager
Team Lead
Project Members
Client

Allow appropriate multi-selection based on existing role architecture.

Recommended default:

Organization Admin
Finance
Project Manager

Do not expose cost information to normal project members or clients by default.

IMPORTANT:
Do not create a second role/permission system.
Reuse the existing Tazq roles and permissions.

==================================================
21. IMPORTANT ARCHITECTURAL PRINCIPLE
==================================================

Project Settings is the CONTROL CENTER for how a project behaves.

It should NOT become a dumping ground for every project feature.

Settings should answer:

“What capabilities are enabled for this project?”

“What methodology does this project use?”

“Who can access what?”

“What can clients do?”

“What information is visible?”

“What notifications are generated?”

“What financial information is tracked?”

Do not put operational records inside Settings.

For example:

Finance Settings:
→ Configure Finance.

Finance tab:
→ Actually manage budgets and expenses.

Planning Settings:
→ Configure Planning.

Planning tab:
→ Actually build the project plan.

Quality Settings:
→ Configure Quality.

Quality tab:
→ Actually manage Test Cases and Defects.
